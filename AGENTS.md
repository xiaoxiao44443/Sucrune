# Sucrune development

- The current Android development version is `0.8.0-agent-dev` (versionCode 8). Its real Android 15 foreground DSH Agent suite passed 63/63 (59 prerequisites + four Agent cases). Use `docs/validation/android15-dsh-agent-acceptance.json` for the real tool/artifact, restart/resume and cancel/reuse result. The earlier 11/11 process/terminal suite is a separate historical run. Do not count offline or UID 2000 probes as model acceptance.
- Target ordinary, non-root Android applications on Android 10 and later (minSdk 29). Keep targetSdk independent.
- Go owns the shared management core; Kotlin owns Android lifecycle, supervision, UI and IPC. C/assembly implement the bundled-program backend and the developing ARM64 Linux compatibility profile. This is not a production hostile-code security boundary.
- Load Go only in the manager process. Native guest workers must not load the Go runtime or share ownership of its signal handlers.
- ARM64 is the execution target. x86_64 supports management builds and AVD mechanism research; Linux guest execution is explicitly unsupported there.
- Never execute a host command and present it as Linux guest execution. Unsupported commands, syntax and capabilities must fail explicitly.
- Keep executeProgram restricted to its bundled no-libc Shell/musl-smoke/Lua catalog. The explicitly authorized Linux development profile uses executePath for imported ARM64 project files, including PT_INTERP and dynamic libraries. It must resolve every executable/interpreter/library through the project broker, never Android host executable paths. Streaming imports verify length/SHA256, atomically publish regular files, and set execute permission only when explicitly requested. New general-program support does not establish an audited hostile-code security boundary.
- Describe the guest libc as Zig's musl-based Linux libc. musl supplies startup/TLS and other routines; Zig also supplies libc implementations, including the allocator. Do not call the whole linked libc unmodified upstream musl or attribute allocator tests to musl's allocator. Sucrune does not patch the vendored Lua interpreter source.
- Static musl programs own guest TLS. SIGSYS must enter through the assembly gate that restores host TPIDR_EL0 and x18 before C, then restores guest state before sigreturn. Save/restore the original host TLS on guest exit. Never call Bionic while guest TLS is installed.
- Keep guest signal masks and guest sigaltstack registrations separate from Android host masks and signal stacks. The Linux profile delivers standard self-directed signals and child-exit SIGCHLD through ARM64 guest frames. Honor SA_ONSTACK when constructing those frames. Its thread-clone subset uses Bionic pthreads with private host TLS and signal stacks, with real joins before clearing guest TIDs. A Linux clone without CLONE_SETTLS inherits the caller's guest TP. Its process-clone subset uses a dedicated Bionic fork supervisor, real kernel COW and a separate filtered guest thread in the child. Preserve guest GPRs, TLS, x18 and FPSIMD when resuming. The Linux process subset supports shared-VM vfork with a private raw supervisor arena and a CLOEXEC completion channel. Only the calling guest thread waits for child exec or exit. Preserve the private project broker session and child ownership across nested forks. Realtime queues and broader job control require separate implementation and evidence.
- Fixed-address ET_EXEC loading must never clobber host mappings. Check address reservation and fail on collision. Guest memory syscalls only operate on the bounded data arena; do not forward arbitrary mmap/mprotect/munmap arguments to the host.
- The Linux profile owns a sparse guest reservation plus any exact ET_EXEC island. MAP_FIXED may replace only VMAs in those owned ranges; never use it against an unowned host range. Install the filter for the full guest ranges once, so subsequently loaded libraries/JIT code cannot bypass syscall translation. Keep a logical VMA map for pointer checks; reservation alone grants no readable/writable access. Preserve file mapping semantics or fail explicitly when unimplemented.
- W^X remains the default memory policy. An explicit executePath environment option SUCRUNE_MEMORY_POLICY=linux-jit permits anonymous writable-executable pages only inside the primary guest reservation for V8/Linux JIT compatibility. Record the policy in native results; never enable it silently or extend it to file snapshots/ELF segments or host addresses. This option does not make the runtime a hostile-code sandbox.
- Serialize shared guest VMA/FD/signal state and complete broker transactions. Release the state lock before futex, local pipe/event waits, thread-clone supervisor waits, blocking wait4 and host joins. For a process fork, retain the lock through the per-process broker snapshot and kernel COW cut. Its fork supervisor and child bootstrap must run independently of that lock. Pin one open description across readv/writev. Use stable per-entry aliases for epoll identity. Publish pipe descriptors and copy their numbers in one locked transaction.
- Linux execution starts a packaged native PIE child of the isolated Kotlin worker to avoid ART address collisions. It owns no Go/ART runtime. Normal reports require parent waitpid. exit_group with live guest threads reports process_exit_group cleanup truthfully, then exits without first freeing live mappings; parent waitpid plus output/broker EOF and feeder completion establish reclamation. Never label this path thread_joined or handler_restored.
- The bundled-program profile offers in-process exec between /bin/lua, /bin/musl-smoke and /bin/sucrune-sh. The Linux fork-child profile supports execve of project ARM64 ELF files with a project PT_INTERP. Snapshot the program and interpreter through the child's broker, validate their immutable bytes and encode a bounded private startup packet. The baseline-filter supervisor re-execs the installed runner with its physical PID intact. Preserve the supplied guest argv[0], environment, inherited policy and per-alias CLOEXEC decisions. Preflight errors return to the old guest. Failures after irreversible replacement terminate the child.
- Keep exec chains within the original execution ID, deadline policy, cancellation and four cleanup barriers. Enforce the 32-successful-replacement limit. Preserve cwd, virtual signal mask, remaining stdin and non-CLOEXEC descriptor offsets; apply virtual CLOEXEC only on committed exec. Fresh image/stack/TLS/data-arena state must not inherit the old image's contents.
- Ordinary commands default to a 30-minute deadline. Explicitly resident Linux path executions have no elapsed-time deadline. Each project accepts one ordinary execution alongside resident executions, within the Android manager's global limit of four. The app calls deleteProject to stop owned executions, wait for cleanup and remove the project. The low-level env.delete guard still rejects active work. See docs/project-lifecycle.md.
- Linux path executions provide 1,024 guest FD slots and keep diagnostic syscall counts without killing the guest on a cumulative threshold. Preserve the limit through fork and exec and report it via RLIMIT_NOFILE. Keep build-only I/O and network behavior independent of FD capacity. The bundled Shell and program backend retains its smaller 64-descriptor profile and also has no cumulative syscall limit. Socket and PTY quotas remain independent.
- Guest descriptor numbers are separate from opaque broker handles. Dup aliases share one open description, offset and status flags. FD_CLOEXEC belongs to each descriptor. Release the original input reader only after its last alias closes. Kotlin retains ownership of output PFDs until worker cleanup. Failed dup/dup3/fcntl validation must preserve the target. Check guest capacity before broker open can create or truncate files.
- Shell exec requires explicit absolute paths and exports all current shell variables; no PATH search or shebang. Successful exec never returns to nested shell frames. Accept at most one input and one output file redirection per command, preserve lexical order, and expand both paths before I/O. Save affected descriptors with F_DUPFD_CLOEXEC, use real dup3 remapping, and restore mappings plus original flags/closed state on returned commands or partial failure. Successful exec must close every backup, including nested-frame saves. Reject duplicate redirects, descriptor syntax and here-documents before the command opens files.
- Keep the Agent outside the runtime. RuntimeClient is currently an in-app API, not a published cross-app IPC SDK.
- Upper-layer apps supply the Linux userland for their projects. Git, curl, CPython, BusyBox, ripgrep and jq in the compatibility suite are androidTest fixtures. See `docs/linux-toolbox.md` for the tool profiles, device commands and known limits.
- Project files, supported connected TCP descriptions and PTY state have distinct broker ownership rules across fork. Isolated processes use a manager-created PTY master passed through SCM_RIGHTS. The manager retains the slave when Android rejects its handoff. Validate the owning terminal and session before opening /dev/tty or setting the foreground group. For cleanup of a child that calls setsid, collect actual kernel wait status and verify ECHILD before declaring descendant reaping complete.
- Network policy defaults to `none`. Linux path executions can request `SUCRUNE_NETWORK_POLICY=loopback` or `outbound`. Only the combination of `build` and `loopback` may translate a guest UDP wildcard bind at port zero into an actual IPv4 or IPv6 loopback bind. Preserve the authorized network policy and Android network snapshot across child exec. Keep secret values out of durable requests, log output and validation evidence. Synthetic bridge values and unauthenticated TLS probes have their own evidence scope.
- Linux runner diagnostics are opt-in. `SUCRUNE_TRACE_SYSCALLS=1` emits bounded syscall diagnostics to stderr. `SUCRUNE_TRACE_FAULTS=1` emits signal information and classified PC/fault locations when the main runner terminates on a fatal signal. Keep raw host addresses out of these reports.
- Persist files separately from execution state. Reopening the manager marks unfinished executions lost; never imply killed processes resume or that uncommitted live output survives.
- Do not release an execution's environment until the worker has died (or RUN was never sent), both output pipes reached EOF, all manager-side broker sessions released their completion references, and the finite or interactive stdin feeder has closed and completed. Binder death alone is insufficient.
- Existing program/path stdin is a copied, finite ByteArray of at most 1 MiB. Explicit executePathInteractive keeps input open for request/response workflows, accepts copied chunks atomically with a cumulative 1 MiB budget, and drains queued bytes before explicit EOF. Only the feeder owns/closes its writer; cancellation, timeout, peer closure and worker completion abort pending input and finish before releasing the environment. Input must remain bounded even for many tiny writes. Transfer read-end ownership to native exactly once; never retain an untracked duplicate reader after transfer. Explicit guest aliases share that owned reader and keep it alive until the final reference closes. Keep the writer nonblocking, suppress SIGPIPE, and check cancellation, deadline and worker completion while feeding. Distinguish accepted, written and guest-consumed bytes; never persist input contents or imply interactive sessions resume after manager death.
- Use one trusted manager per data directory. The Go instance lock and bridge cache do not implement cross-process locking or defend against hostile same-UID writers.
- Keep SDK, JDK and cache paths local and untracked. Do not alter a neighboring project's files or caches.
- Cancellation, input-deadline expiry and feeder failure must enqueue their main-handler stop/failure decision before aborting input: closing stdin can itself produce a guest RESULT. A stopped guest may observe terminal EOF before it is killed; assert no EOF before stop, then verify the terminal reason and cleanup barriers. When a running persisted snapshot loses its live session during lookup, reread durable state rather than returning a stale running record without runtime information.
- Run `scripts/test-core.ps1` for Go changes. Run `scripts/build-android.ps1 -Zig <Zig-0.17.1-path>` for Android/native integration; it prepares the trusted Linux programs and both Go ABI libraries, builds APKs and runs lint. Direct Gradle/Android Studio use requires `scripts/build-linux-programs.ps1` and `scripts/build-go-android.ps1` first. Keep musl/Zig/Lua notices in source and packaged assets; verify vendored Lua files against their source manifest before building.
- Copying staged source can preserve older modification times and leave Ninja object files stale. Refresh copied source timestamps or clean the affected ABI native targets after syncing; verify the final binary when its behavior disagrees with source. Do not count an incremental build alone as proof that new source was included.
- Host parser tests and compilation do not establish Android execution or isolation. Use `docs/device-validation.md` and report unexecuted checks accurately.
- Current user preference overrides the old uninstall workflow: keep both com.sucrune.probe and com.sucrune.probe.test installed, preserve the matching signing key, and use adb install -r for subsequent builds. Do not uninstall or use pm clear for test cleanup.
- After device validation, retain concise verified results and persistent in-app execution history. Remove only session-created test workspaces/receipts, screenshots, raw logs and scratch data. Never delete unrelated data, signing keys, or the whole application/build directory.
